# Realism Browser

Лёгкий браузер для Windows 10/11 (x64). Интерфейс нативный, на Rust (Win32 + Direct2D/DirectWrite). Страницы рендерит Microsoft Edge WebView2 через [wry](https://crates.io/crates/wry) 0.57 и [webview2-com](https://crates.io/crates/webview2-com) 0.39. Главная цель — тратить меньше оперативной памяти, не жертвуя совместимостью с сайтами.

## Скачать

**[⬇ Скачать последнюю версию (Realism-Browser-Setup.exe)](https://github.com/realityunrealengine-cell/realism-browser/releases/latest/download/Realism-Browser-Setup.exe)** · [все релизы](https://github.com/realityunrealengine-cell/realism-browser/releases)

Один файл ~1,2 МБ: запустите и нажмите «Установить». Права администратора не нужны — ярлыки в «Пуск» и на рабочем столе, запись в «Приложениях», Realism появится среди браузеров по умолчанию. Удаление — через «Параметры → Приложения». Файл не подписан цифровой подписью, поэтому Windows SmartScreen может предупредить при первом запуске («Подробнее → Выполнить в любом случае»).

Нужен **Microsoft Edge WebView2 Runtime**. В Windows 11 он уже стоит, в Windows 10 обычно ставится вместе с Edge. Если его нет, установщик подскажет ссылку.

## Обновления

Меню **⋯ → Проверить обновления** (или `realism://about`). Браузер сам проверяет раз в день наличие нового релиза в этом репозитории (GitHub Releases API, можно отключить), показывает метку на кнопке меню и пункт «Доступно обновление». По кнопке скачивает установщик из релиза, сверяет его **SHA-256** (digest ассета GitHub и `SHA256SUMS.txt`), затем запускает тихую установку и закрывается; установщик дожидается закрытия, заменяет `realism.exe` и снова запускает браузер — вкладки восстанавливаются.

Выпуск новой версии: поднять `version` в `Cargo.toml`, собрать (`cargo build --release`, затем `cd installer && cargo build --release`) и выполнить `tools/release.ps1`.

## Что реализовано

| Функция | Как сделано |
|---|---|
| Вкладки | Вкладки нарисованы прямо в заголовке окна; поддерживаются Snap Layouts Windows 11. Есть открытие, закрытие, перетаскивание, переключение колесом мыши, контекстное меню (дублировать, звук, «усыпить», закрыть другие/справа) и анимации |
| Адресная строка | Распознаёт URL, `localhost`, IP и пути к файлам; остальное уходит в поиск Google / Bing / DuckDuckGo. Подсказывает из истории и закладок (стрелки ↑/↓, Alt+Enter — новая вкладка). Показывает статус HTTPS: замок, «не защищено», ошибку сертификата |
| Навигация | Назад, вперёд, обновить/стоп, жёсткое обновление без кэша, масштаб. Масштаб запоминается для каждого сайта |
| Стартовая страница | **Нативная, без WebView2:** пустая вкладка не стоит ни одного процесса движка. Плитки частых сайтов, поиск |
| Закладки | Папки, панель закладок (Ctrl+Shift+B), звёздочка в адресной строке, менеджер `realism://bookmarks`: добавить, изменить, переместить, удалить |
| История | Каждый визит записывается, включая SPA-переходы. Страница `realism://history`: поиск, группировка по дням, удаление |
| Загрузки | Свой менеджер `realism://downloads`: прогресс, скорость, оставшееся время, пауза, продолжение, отмена, «открыть», «показать в папке». Кольцо прогресса на кнопке в тулбаре. Папку можно сменить, есть режим «спрашивать, куда сохранить» |
| Сессия | Вкладки и окна восстанавливаются после перезапуска **лениво**: загружается только активная вкладка, остальные — при открытии. Сохраняется история «Назад» по URL. Ctrl+Shift+T возвращает закрытые вкладки |
| Приватные окна | Отдельный временный профиль WebView2 (InPrivate). Не пишут историю, сессию, загрузки, масштаб и разрешения на диск. Оформлены иначе |
| Разрешения сайтов | Своя панель-запрос: камера, микрофон, геолокация, уведомления и т. д. Решения хранятся по origin; список и сброс — в настройках и в меню замка |
| Всплывающие окна | Окна, открытые действием пользователя, открываются вкладкой рядом с исходной; `window.opener` сохраняется, поэтому работают OAuth-входы. Окна без действия пользователя блокируются, при этом показывается панель «Открыть / Всегда разрешать» |
| Полноэкранный режим | F11 и полноэкранный режим из HTML5 (видео на YouTube) |
| Темы | Тёмная (фирменная), светлая и «как в Windows». Сайты получают `prefers-color-scheme` |
| Безопасность | Стандартная проверка HTTPS и сертификатов WebView2 с блокирующей страницей, SmartScreen. Внутренние страницы защищены случайным токеном на каждый запуск, CSP и `frame-ancestors 'none'`: сайты не могут вызвать их API |
| Прочее | Печать (Ctrl+P), поиск на странице (Ctrl+F), DevTools (F12), один экземпляр на профиль (ссылки из других программ открываются вкладками), обработка падений страниц и движка |

## Оптимизация памяти

1. **Интерфейс без браузерного движка.** Вкладки, тулбар, меню и стартовая страница рисуются через Direct2D в *программный* DC render target, без D3D-устройства и swap chain. Процесс интерфейса занимает ~7–14 МБ private working set. Внеэкранный буфер освобождается, когда он больше не нужен.
2. **Стартовая страница без WebView2.** Браузер без открытых сайтов — это один процесс на ~8 МБ.
3. **Ленивый движок.** WebView2 (браузерный процесс, GPU, сеть, хранилище) запускается только при первой навигации. Чтобы переход был быстрым, разогрев начинается, когда вы начинаете печатать в адресной строке. Если не осталось ни одной загруженной вкладки, движок полностью останавливается: через 20 с в режиме «Экономия», через 2 мин в «Сбалансированном».
4. **Smart Tab Sleeping** работает по ступеням:
   * скрытая вкладка → `IsVisible=false`: WebView2 замедляет таймеры и не рисует;
   * через N секунд → `MemoryUsageTargetLevel=LOW` (WebView2 освобождает кэши рендерера);
   * дальше → `TrySuspend` (вкладка заморожена, 0 % CPU);
   * затем — полная **выгрузка** WebView: остаются только URL, заголовок, иконка и история «Назад». При возврате на вкладку она восстанавливается.
   * Вкладки **не усыпляются**, если в них играет звук, работает камера или микрофон, идёт загрузка файла, ждёт ответа запрос разрешения, есть **несохранённый ввод в форме** (отслеживается встроенным скриптом) или сайт в списке исключений. Приватные вкладки только замораживаются, но не выгружаются, иначе закончилась бы приватная сессия. Спящая вкладка отмечена значком луны и приглушённым заголовком.
5. **Режимы работают по-настоящему** (`src/app.rs`, `Mode::policy`):

| | Экономия памяти | Сбалансированный (по умолчанию) | Макс. производительность |
|---|---|---|---|
| LOW memory target | сразу при скрытии | через 10 с в фоне (после загрузки) | только при заморозке |
| Заморозка (TrySuspend) | через 20 с | через 2 мин | через 30 мин |
| Выгрузка | через 5 мин | через 30 мин | никогда |
| Живых фоновых вкладок (LRU) | ≤ 3 | ≤ 12 | без лимита |
| Остановка движка без вкладок | через 20 с | через 2 мин | никогда, движок прогревается при запуске |
| Вкладки одного сайта | один общий процесс (`--process-per-site`) | отдельные процессы | отдельные процессы |
| Запасной рендерер Chromium | отключён | отключён | включён |

6. **Свёрнутое окно:** активная вкладка скрывается для WebView2, поэтому таймеры замедляются и отрисовка останавливается. После таймаута вкладка тоже может заморозиться.
7. **Минимум фоновой работы:** таймер анимации работает только во время анимации или загрузки. Единственный постоянный таймер срабатывает раз в 10 с: он обновляет индикатор RAM и проверяет политику сна.
8. **Хранилище — системный SQLite** (`winsqlite3.dll` из Windows): ноль байт в бинарнике, кэш страниц ограничен 512 КБ.
9. Release-профиль: LTO, `codegen-units=1`, `panic=abort`, strip. Размер exe — ~0,9 МБ.

### Монитор ресурсов `realism://performance` (Shift+Esc)
Показывает реальные данные Windows по всему дереву процессов: private working set, commit, CPU по каждому процессу (тип процесса берётся из `GetProcessExtendedInfos` WebView2). Также видно число активных, замороженных и выгруженных вкладок и память каждой вкладки: процессы-рендереры сопоставляются с вкладками через FrameId главного фрейма. Здесь же указано, почему конкретная вкладка не усыпляется, и есть кнопка «Освободить память», которая показывает «было / стало».

## Ограничения (WebView2 / текущая версия)

* Расширения из Chrome Web Store, синхронизация аккаунта и встроенный менеджер паролей с UI недоступны. Автосохранение паролей WebView2 включено в обычных окнах.
* DRM: WebView2 поддерживает PlayReady, но **не Widevine**, поэтому часть стриминговых сервисов (например, Netflix) может не воспроизводить видео.
* Выгруженная вкладка при восстановлении теряет состояние формы и прокрутку. Поэтому вкладки с введённым текстом не выгружаются. История «Назад» восстанавливается по URL, «Вперёд» — нет.
* Вкладку нельзя перетащить в другое окно. Всплывающие окна открываются как вкладки, а не отдельными окнами.
* Флаги процесса движка (`--process-per-site`, запасной рендерер) применяются при следующем запуске движка: после перезапуска браузера или после автоматической остановки без вкладок.
* При очень большом числе вкладок (>~25 на 1280 px) полоса вкладок не прокручивается.
* Reddit на тестовой машине показал проверку reCAPTCHA. Это защита сайта от ботов, она зависит от IP и нового профиля; страница сама по себе работает.
* Servo как альтернативный движок не подключён: первая версия ориентирована на совместимость с сайтами.

## Сборка

Нужны Rust (MSVC) и Visual Studio Build Tools (C++ и Windows SDK — для `rc.exe` и компоновщика).

```bash
cargo build --release                      # target\release\realism.exe, realism-bench.exe
cargo test --bin realism                   # модульные тесты: URL, БД
cd installer && cargo build --release      # installer\target\release\realism-setup.exe (встраивает realism.exe)
```

Структура:

```
src/main.rs        вход, цикл сообщений, один экземпляр, отложенные диалоги
src/app.rs         состояние: окна, вкладки, навигация, загрузки, разрешения, всплывающие окна, сессия
src/ui.rs          нативное окно: заголовок с вкладками, тулбар, адресная строка, панели, стартовая страница
src/popup.rs       нарисованные меню и подсказки адресной строки
src/memory.rs      Smart Tab Sleeping, остановка движка, данные монитора ресурсов
src/webview.rs     окружение WebView2, создание вкладок (wry) и события (webview2-com)
src/pages.rs       realism:// страницы и их JSON API
src/gfx.rs         Direct2D/DirectWrite, иконки сайтов через WIC
src/db.rs          SQLite через системный winsqlite3.dll
src/procmem.rs     замер памяти и CPU дерева процессов (общий с бенчмарком)
src/bin/realism-bench.rs   сравнение с другими браузерами
assets/            HTML/CSS/JS встроенных страниц, иконка
installer/         установщик / деинсталлятор
```

## Как воспроизвести сравнение

```bash
target\release\realism-bench.exe --runs 3 --idle-runs 2 --idle-minutes 5 --out bench
```

Для каждого запуска создаётся новый временный профиль, окно 1280×800, одинаковые URL (Google, Wikipedia, YouTube) и одинаковое время ожидания. Звук выключен у всех браузеров (`--mute-audio`), автовоспроизведение разрешено всем одинаково. Перед замерами каждый браузер один раз запускается вхолостую, чтобы прогреть кэш диска и антивируса. Память суммируется по **всему дереву процессов** браузера. Результат — `bench/results.md` и `bench/raw.csv`.

## Итоги замеров (медиана, физическая RAM всего дерева процессов)

| Сценарий | Realism (по умолчанию) | Realism (Экономия) | Chrome | Edge |
|---|---:|---:|---:|---:|
| Запуск без вкладок | **9 МБ** | 9 МБ | 224 МБ | 220 МБ |
| about:blank | **73 МБ** | 75 МБ | 171 МБ | 158 МБ |
| Google | **154 МБ** | 156 МБ | 229 МБ | 222 МБ |
| 5 вкладок Wikipedia | 220 МБ | **155 МБ** | 423 МБ | 406 МБ |
| 10 вкладок Wikipedia (~25 с) | 324 МБ | **284 МБ** | 654 МБ | 659 МБ |
| 10 вкладок после 5 мин | **229 МБ** | 238 МБ | 499 МБ | 334 МБ* |
| Видео YouTube | **500 МБ** | 500 МБ | 531 МБ | 536 МБ |

Время до появления окна: Realism ~100–140 мс, Chrome 260–430 мс, Edge 275–580 мс.

**Честные оговорки:**
* **Commit** (выделенная память) в «Сбалансированном» режиме при многих вкладках **выше, чем у Chrome**: +38 % на 10 вкладках. Уровень `MemoryUsageTargetLevel=LOW` вытесняет страницы фоновых вкладок из физической памяти, а не освобождает их. Физическая RAM действительно отдаётся другим программам, но при возврате на вкладку страницы подгружаются обратно. Режим «Экономия памяти» снижает и commit: −50 % против Chrome на 10 вкладках, потому что вкладки одного сайта делят процесс, а лишние выгружаются.
* Значение «10 вкладок через ~25 с» в «Сбалансированном» режиме снято сразу после понижения приоритета памяти. Без дальнейшей заморозки фоновые рендереры за ~30 с возвращаются примерно к 33 МБ каждый, всего ~475 МБ. После заморозки на 2-й минуте общий объём стабилизируется около 230 МБ.
* \* У Edge в сценарии «после 5 мин» большой разброс (201 и 467 МБ), медиана двух запусков — 334 МБ.
* На одной тяжёлой вкладке (YouTube) выигрыш небольшой, 6–16 %: страницу рендерит тот же Chromium.

Полные таблицы с CPU, commit, числом процессов и временем старта — в [`bench/results.md`](bench/results.md).
